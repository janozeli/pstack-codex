# pstack runtime for Codex

These are the native execution contracts for this distribution. Host instructions and live tool schemas take precedence. All skill files, playbooks, and supporting references are shipped in this package. Resolve paths relative to the installed package; do not fetch another distribution to execute a skill. <pstack skills dir> is this package's skills directory, the parent of the poteto-mode skill folder.

## Delegation

Use `spawn_agent` when the host permits native delegation. Pass task_name and message. For an explicitly configured model or effort, use fork_turns: none when required and provide the full brief. Collect results with wait_agent.
spawn_agent children share the parent's checkout, so give each writer its own git worktree (git worktree add <path> -b <branch> <base>) and pass that path in its brief. codex --worktree starts a whole session in a managed worktree, and codex cloud exec --env <id> --branch <base> runs a task on a cloud machine whose diff you apply locally. In T3, follow its delegation contract for different providers, explicit settings, background work, and isolated worktrees. That tool creates the child's checkout. Never create a child's checkout in the shell there. Native worktrees isolate files, not machines, processes, ports, or credentials. If a separate machine is required, verify an actual remote environment is available before executing that lane.
Read-only is an instruction unless the host enforces a sandbox: say do not edit, select tools consistent with the task, and inspect git status afterward. Preserve the requested model and required MCP access. Use fresh children unless the skill explicitly allows reuse. Follow host completion notifications; do not report a result before receiving it.
For poteto-agent or comment-sicko, begin the child brief by requiring a full read of the corresponding agents/<name>.md file.

## Model configuration

Read $CODEX_HOME/AGENTS.md (default ~/.codex/AGENTS.md), inside the pstack models markers. The default code model is inherit-parent xhigh; the default judgment model is inherit-parent xhigh. A missing role uses its generated default. Each configured value is a model or inherited alias followed by an optional effort, not a single model ID. Split it before dispatch. For bare auto or inherit-parent, inherit both model and effort. With an explicit effort, inherit only the model and pass `reasoning_effort` separately. Do not let an agent type silently change the inherited model.
Use only available model IDs and supported efforts. The budget ladder is max > xhigh > high > medium > low. Fall back to the highest supported effort at or below the request; if none qualifies, leave the role needing a choice. Report overrides imposed by the environment. Pass an explicitly selected native model through model.
Keep the source role list and panel lengths. Inherited aliases belong to the parent's family. Multiple calls or variants from one provider do not satisfy a cross-provider requirement. In T3, a seat from another provider is a delegate_task whose target is a provider that orchestrator_capabilities lists. Outside T3, a role value <provider>:<model> <effort>, with provider codex, claude or grok, is a read-only seat on that provider's CLI: write the complete brief to a file, run node <pstack skills dir>/poteto-mode/scripts/cross-provider.mjs <provider> <model> <effort> <brief file> <output file> <checkout>, and read its reply from the output file. It uses that CLI's own login and billing. A seat whose CLI is missing or fails is reported unmet, never replaced by the parent's model. Use the workflow's explicit fallback, or report that requirement unmet. Do not invent a model catalog or silently substitute a provider the user explicitly required.

## Session evidence

History is under $CODEX_HOME/sessions and archived_sessions (default ~/.codex), as rollout-*.jsonl files or zstd-compressed rollout-*.jsonl.zst files. Validate session_meta.payload.id and payload.cwd.
This conversation's thread ID is $CODEX_THREAD_ID in the shell, and its rollout file name ends with that ID. Never pick the newest file. Resolve symlinks and compare checkout directory boundaries before inspecting conversation content. For deleted paths, resolve the existing ancestor and append the missing suffix. Read only verified relevant checkouts. If identity cannot be established, use an explicitly labeled digest of this conversation; a digest does not prove a complete transcript audit. For history mining, first scope candidates by workspace metadata, then inspect relevant conversations. Subagents are separate conversations.
The installed worktree-audit.sh selects this host's history reader. A review-history bucket requires investigation, not deletion. Chat activity never authorizes cleanup by itself.

## Capability-dependent work

Use the host's plan and question tools. An unanswered required choice is not consent. Keep working toward a finish condition with the built-in /goal command, and block on a PR verdict with the bundled watch-pr script. The Codex CLI has no timed wake: in T3, an hourly tick is schedule_task with an interval bound to this thread, and PR events wake the thread through watch_pull_request. Without them, complete only the current round and report the cadence unarmed. Follow T3's PR watcher lifecycle and linking rules when it is the host.
Verify a CLI or TUI with the bundled control-cli skill and a web, IDE or Electron UI with the bundled control-ui skill. Without a working driver, live verification is incomplete. Unit tests are not a substitute for an interactive lane.
For skill authoring, use the built-in $skill-creator skill; otherwise follow the repository's skill format, validate frontmatter and local links, and test the resulting instructions on the intended task. Before commit, clean code with the bundled deslop skill and prose with the bundled unslop skill. Name the checks actually run.
Use project state tools when available, otherwise keep task IDs, owners, branches, dependencies, evidence, and next actions in project-local notes.md and pass relevant state to children. A fresh child does not inherit another worker's processes: reconstruct and revalidate the environment when a process fork is unavailable.
Bugbot findings are ordinary review threads on the forge: triage them per skills/poteto-mode/references/bugbot-triage.md wherever they appear. When a pull request has no Bugbot check or comment, Bugbot steps do not apply: do not wait for Bugbot, mark its checklist items not applicable, and never relabel a codex review pass as Bugbot.
Automation and webhook work requires a real host integration and secret delivery mechanism. Resolve them before dependent execution. Never invent service URLs, secrets, API fields, or a successful probe. A placeholder may support a draft but cannot satisfy verification or deployment. Keep independent work moving and leave blocked gates explicitly incomplete.
