# pstack runtime for Claude Code

These are the native execution contracts for this distribution. Host instructions and live tool schemas take precedence. All skill files, playbooks, and supporting references are shipped in this package. Resolve paths relative to the installed package; do not fetch another distribution to execute a skill. <pstack skills dir> is this package's skills directory, the parent of the poteto-mode skill folder.

## Delegation

Use `Agent` when the host permits native delegation. Pass prompt and the supported subagent_type. The bundled delegate agents are pstack:poteto-agent and pstack:comment-sicko. pstack:poteto-mode is the main-session coordinator started with claude --agent; never spawn it. Give each child its absolute skill path and complete task context.
Give each writer its own checkout with the Agent isolation: "worktree" field. claude --worktree starts a whole session in a new worktree, and claude --cloud with --environment <id> runs a session on a separate cloud machine. In T3, follow its delegation contract for different providers, explicit settings, background work, and isolated worktrees. That tool creates the child's checkout. Never create a child's checkout in the shell there. Native worktrees isolate files, not machines, processes, ports, or credentials. If a separate machine is required, verify an actual remote environment is available before executing that lane.
Read-only is an instruction unless the host enforces a sandbox: say do not edit, select tools consistent with the task, and inspect git status afterward. Preserve the requested model and required MCP access. Use fresh children unless the skill explicitly allows reuse. Follow host completion notifications; do not report a result before receiving it.
Keep native foreground children in the foreground when the host requires it. Do not force background execution through agent metadata.

## Model configuration

Read $CLAUDE_CONFIG_DIR/rules/pstack-models.md (default ~/.claude/rules/pstack-models.md). The default code model is inherit-parent xhigh; the default judgment model is opus xhigh when available, otherwise a role needing a choice. A missing role uses its generated default. Each configured value is a model or inherited alias followed by an optional effort, not a single model ID. Split it before dispatch. For bare auto or inherit-parent, inherit both model and effort. With an explicit effort, inherit only the model and pass `effort` separately. Do not let an agent type silently change the inherited model.
Use only available model IDs and supported efforts. The budget ladder is max > xhigh > high > medium > low. Fall back to the highest supported effort at or below the request; if none qualifies, leave the role needing a choice. Report overrides imposed by the environment. Native Claude model aliases resolve to the host's current version. Per-invocation effort needs Claude Code 2.1.292 or later; CLAUDE_CODE_EFFORT_LEVEL can override it.
Keep the source role list and panel lengths. Inherited aliases belong to the parent's family. Multiple calls or variants from one provider do not satisfy a cross-provider requirement. In T3, a seat from another provider is a delegate_task whose target is a provider that orchestrator_capabilities lists. Outside T3, a role value <provider>:<model> <effort>, with provider codex, claude or grok, is a read-only seat on that provider's CLI, for roles that answer with a reply, such as a judge or reviewer; a seat that must write files needs a native or T3 delegate: write the complete brief to a file, run node <pstack skills dir>/poteto-mode/scripts/cross-provider.mjs <provider> <model> <effort> <brief file> <output file> <checkout>, and read its reply from the output file. It uses that CLI's own login and billing. A seat whose CLI is missing or fails is reported unmet, never replaced by the parent's model. Use the workflow's explicit fallback, or report that requirement unmet. Do not invent a model catalog or silently substitute a provider the user explicitly required.

## Session evidence

History is under $CLAUDE_CONFIG_DIR/projects (default ~/.claude/projects), one folder per workspace named after its path with each / and . replaced by -. Validate sessionId and cwd; file-history snapshots can precede conversation records.
This conversation's session ID is the value the poteto-mode, reflect and show-me-your-work skills state when invoked. A skill file opened with Read shows the unsubstituted placeholder instead, and then the ID is unavailable. Its transcript is <workspace folder>/<session ID>.jsonl, and its subagents are under <session ID>/subagents/. Never pick the newest file. Resolve symlinks and compare checkout directory boundaries before inspecting conversation content. For deleted paths, resolve the existing ancestor and append the missing suffix. Read only verified relevant checkouts. If identity cannot be established, use an explicitly labeled digest of this conversation; a digest does not prove a complete transcript audit. For history mining, first scope candidates by workspace metadata, then inspect relevant conversations. Subagents are separate conversations.
The installed worktree-audit.sh selects this host's history reader. A review-history bucket requires investigation, not deletion. Chat activity never authorizes cleanup by itself.

## Capability-dependent work

Use the host's plan and question tools. An unanswered required choice is not consent. Re-check a finish condition with the built-in /loop command, at an interval such as /loop 1h or self-paced, and wake on PR events with the Monitor tool around the bundled watch-pr script. In T3, PR events also arrive through watch_pull_request. Follow T3's PR watcher lifecycle and linking rules when it is the host.
Verify a CLI or TUI with the bundled control-cli skill and a web, IDE or Electron UI with the bundled control-ui skill; Claude Code's --chrome browser is another driver for control-ui. Without a working driver, live verification is incomplete. Unit tests are not a substitute for an interactive lane.
For skill authoring, use the skill-creator plugin from the claude-plugins-official marketplace when it is installed; otherwise follow the repository's skill format, validate frontmatter and local links, and test the resulting instructions on the intended task. Before commit, clean code with the bundled deslop skill and prose with the bundled unslop skill. Name the checks actually run.
Use project state tools when available, otherwise keep task IDs, owners, branches, dependencies, evidence, and next actions in project-local notes.md and pass relevant state to children. A fresh child does not inherit another worker's processes: reconstruct and revalidate the environment when a process fork is unavailable.
Bugbot findings are ordinary review threads on the forge: triage them per skills/poteto-mode/references/bugbot-triage.md wherever they appear. When a pull request has no Bugbot check or comment, Bugbot steps do not apply: do not wait for Bugbot, mark its checklist items not applicable, and never relabel a Claude Code /code-review pass as Bugbot.
Automation and webhook work requires a real host integration and secret delivery mechanism. Resolve them before dependent execution. Never invent service URLs, secrets, API fields, or a successful probe. A placeholder may support a draft but cannot satisfy verification or deployment. Keep independent work moving and leave blocked gates explicitly incomplete.
